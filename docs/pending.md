## Task 17 — synthetic end-to-end integration test (`tests/test_integration.py`)

Manual run: `uv run pytest -m slow -v -s`, 2026-09-28, CPU (`--device cpu`), whisper `small.en` (downloaded fresh, 480 MB, to `~/.cache/music-transcribe/ggml-small.en.bin`), demucs `htdemucs_6s` (weights already in `~/.cache/huggingface/hub`). Runtime: 156 s total (well under the 10 min budget).

**Result: FAILED** on the chord/loop assertion. Everything else the test checks passed: CLI exit 0, `bpm` 60.1 (in range), `key` "Bbm" (expected), `render/cifra.html` present, guitar/bass stems separated, 41 guitar notes + 34 bass notes extracted by basic-pitch.

Two real findings, not weakened or worked around in the test:

1. **Phantom pickup bar from `fit_grid`.** The synthetic song's first bass root-change lands essentially at t≈0 (fixture starts hard on beat 1, no lead-in). `fit_grid`'s "shift bar0 to at-or-before the first change" rule (by design, per its docstring and `tests/test_grid.py::test_fit_grid_first_bar_at_or_before_first_change`) then pushes `bar0` a full bar early (`bar0 = -3.967`, `bar_len = 3.993`), inserting a near-empty spurious bar 1 before the real audio and shifting every subsequent bar's index by one. The mechanism is intentional (handles real songs with a pickup measure) but a song with zero lead-in triggers it as a false positive. Plausible on real recordings that start exactly on the downbeat, not just synthetic fixtures.
2. **Chord misnaming from harmonic overtones.** The pad triad for the Db bar (`Db4, F4, Ab4`, i.e. Db major) gets named `"Absus4/Db"` instead of `"Db"`. `chord_for_bar` (`src/music_transcribe/harmony/chords.py`) scores by raw template dot-product with no bonus for "root = bass note" beyond the existing mismatch penalty; the pad's 3rd harmonic (each tone's own overtone series, `sine_note(harmonics=4)`) adds energy a perfect fifth above each fundamental, which happens to reinforce an alternate root (Ab) enough to outscore the intended Db major reading. This is a genuine limitation of the simple template-matching heuristic, not unique to sine waves — any harmonically rich real instrument tone has the same overtone structure.
3. **Lyrics stage doesn't reach `[]` on this instrumental fixture.** `lyrics.json` came back with 7 lines of hallucinated text (`". . ."` / `". ."`, confidence 0.5) instead of `[]`. `parse_whisper_json`'s `NON_SPEECH` filter (`src/music_transcribe/lyrics.py`) only drops known tokens like `"[MUSIC]"`/`"♪"`; it doesn't recognize whisper's punctuation-only hallucination pattern on silent/wordless audio, so these lines pass through. The assertion `lyrics.json == []` was never reached because the test failed earlier on the chord assertion, but inspecting the tmp output shows this would also have failed.

None of these are fixed by this task (Task 17 is fixture + test only, not pipeline changes) — they are handed off as concrete follow-ups against `src/music_transcribe/harmony/grid.py`, `src/music_transcribe/harmony/chords.py`, and `src/music_transcribe/lyrics.py`. `tests/test_integration.py` is committed as written in the brief (marked `slow`, excluded from the default `-m 'not slow'` run) so it stands as a reproducible regression case once those are addressed.
